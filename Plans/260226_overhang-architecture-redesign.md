## 1. Current Architecture

### 3-Enzyme Golden Gate Assembly

The pipeline uses three enzymes in two levels:
- **BsaI**: Flanks the 5'WT gene blocks (cuts to produce oh1 and oh_L/oh4 overhangs)
- **BsmBI**: Flanks the 3'WT gene blocks, PolIII, and barcode region (oh2, oh3 overhangs)
- **PaqCI**: Level 2 cloning into backbone

### Overhang Roles

| Overhang | Enzyme | Source | Role |
|----------|--------|--------|------|
| oh_L | BsaI | Gene-derived (nt 1-4) | First 4 nt of gene, fixed |
| oh1 | BsaI | Gene-derived at tile start | 5'WT → tile junction |
| oh2 | BsmBI | Gene-derived at tile end | Tile → 3'WT junction |
| oh3 | BsmBI | PolIII-derived (freely chosen) | 3'WT → barcode junction |
| oh4 | BsaI | Freely chosen from HF set | Barcode → PaqCI junction |

### Current Superblock System (Being Replaced)

The current system uses **global** superblock boundaries:
1. `compute_global_superblock_boundaries()` — finds split points for the longest 3'WT and 5'WT regions using DP
2. `assign_global_boundaries_to_tiles()` — assigns global splits to individual tiles, dropping undersized sub-blocks
3. `dp_solve_superblock_splits()` — the DP itself, using score = `10 * in_HF + fidelity`

**Problems with the current system:**
- **BUG-005**: Global splits are computed for the largest WT region, then assigned per-tile. Tiles near the crossover point get sub-blocks that are too small (dropped by min_sub_length check) or too large after merging (exceeds max_sub_length). Example: AKAP11 tile 20's 3'WT = 1885 nt > 1778 limit.
- **Global overhang exclusion**: `exclude_ohs` contains ALL oh2 values from all tiles, severely limiting candidate overhangs. This causes false "no valid solution" failures.
- **No block reuse optimization**: Tiles within the same region don't share blocks efficiently.

### Current Scoring

Individual overhang fidelity (context-independent):
```
fidelity(X) = M[X][RC(X)] / sum(M[X][*])   (all 256 possible partners in denominator)
```

DP score per boundary: `10 * (oh in HF set) + fidelity(oh)`

This is identical to OOGGA's fidelity formula (see Section 2).

## 2. OOGGA Research Findings

### Source

- **Paper**: Mukundan & Madhusudhan 2025, bioRxiv 10.1101/2025.06.16.659877 (PREPRINT)
- **GitHub**: github.com/bigbigdumdum/OOGGA (Python)
- **Deep research completed**: 2026-02-26

### OOGGA's Scoring Function

OOGGA uses TWO per-overhang metrics from the Potapov 256×256 T4 DNA Ligase matrix:

```python
P_fid(X) = M[X][RC(X)] / sum(M[X][*])         # individual fidelity (same as ours)
P_eff(X) = M[X][RC(X)] / max_Y(M[Y][RC(Y)])   # relative efficiency
```

The DP optimizes:
```
Score = [Product_i(P_eff_i)]^w_eff × [Product_i(P_fid_i)]^w_fid
```

Where `w_eff` and `w_fid` are configurable weights (both default to 1.0).

### Critical Finding: OOGGA Does NOT Use Pairwise Set Fidelity

**OOGGA only uses the diagonal of the Potapov matrix** — i.e., the correct Watson-Crick
count for each overhang. It does NOT compute pairwise cross-reactivity between overhangs
in the set. Cross-reactivity is handled only via a crude sequence identity filter
(`max_overhang_identity = 2` out of 4 bases).

This means OOGGA's scoring is **context-independent**: the score of overhang X doesn't
depend on what other overhangs are in the same reaction.

### Comparison: OOGGA vs Potapov GetSet (Simulated Annealing)

The Potapov Table 1 HF sets were generated by NEB's **GetSet** tool using MCMC simulated
annealing. GetSet uses **context-dependent** set fidelity:

```
p(O_i) = M[O_i][RC(O_i)] / sum_{j in S}(M[O_i][j])   # denominator = only overhangs in the set
```

This is always ≥ the context-independent version (smaller denominator). It more accurately
predicts actual assembly fidelity because in a real GGA reaction, only the overhangs
present compete.

### OOGGA Does NOT Reference HF Sets

OOGGA uses all 256 overhangs as candidates and lets the DP find optimal ones. It does not
use, reference, or incorporate the Potapov Table 1 HF sets.

### Implications for Our Pipeline

| Feature | OOGGA | Our Pipeline | Potapov GetSet |
|---------|-------|-------------|----------------|
| Fidelity model | Context-independent | Context-independent | **Context-dependent** |
| Data used | Diagonal only (256 values) | Diagonal only | Full 256×256 matrix |
| Cross-reactivity | Sequence identity filter | HF set membership + RC check | Full pairwise matrix |
| HF set usage | None | Used for scoring bonus | Used as objective function output |
| Efficiency metric | Yes (P_eff) | **No** — not currently used | N/A |
| Optimization | DP (global optimum) | DP (global optimum) | MCMC SA (near-optimal) |

### Two Scoring Options (To Be Decided)

**Option A — Pure OOGGA-style DP**: Score purely by `P_fid × P_eff` products. No HF set
bonus. Simpler, but loses the set-level optimization captured by Potapov SA.

**Option B — OOGGA DP + HF set upscoring**: Same per-overhang scoring, but add a bonus
when an overhang is in the Potapov Table 1 HF set. This biases toward experimentally
validated overhangs that the SA identified as having low cross-reactivity.

**Recommendation**: Option B adds genuine value because:
1. HF sets encode pairwise interactions not captured by individual fidelity
2. HF sets were experimentally validated (10-fragment and 24-fragment assemblies)
3. The bonus is most valuable for **freely-chosen overhangs** (oh3, oh4, SB junction OHs)
4. For gene-derived overhangs (oh1, oh2), the DP boundary search already constrains choices

**Decision**: Deferred. Implement tile-boundary architecture with CURRENT scoring first.
OOGGA scoring upgrade will be a separate task.

### New Insight: Efficiency Metric

Our pipeline currently does NOT use an efficiency metric. OOGGA's `P_eff` captures ligation
*yield* (how much correct product you get), which is distinct from fidelity (what fraction
of product is correct). Adding P_eff would be straightforward:
```R
max_diagonal <- max(pairwise_matrix_diagonal)  # global max of M[X][RC(X)]
P_eff(X) <- M[X][RC(X)] / max_diagonal
```

## 4. Tile-Boundary Superblock Architecture

### Core Concept

**Superblocks = contiguous groups of tiles.** SB boundaries are constrained to fall at
tile boundaries (no intra-tile splitting). This eliminates the global/local DP coordination
problems (BUG-005) because:

- Each tile belongs to exactly one SB
- The SB boundary overhang is simply the oh2 of the last tile in the SB
- Per-tile overhang exclusion replaces global exclusion

### How It Works

```
Gene: [===tile1===][===tile2===][===tile3===][===tile4===][===tile5===]
SB1:  [===tile1===][===tile2===]
SB2:                             [===tile3===][===tile4===]
SB3:                                                       [===tile5===]
                                ^              ^
                            SB boundary    SB boundary
                            (oh2 of tile2) (oh2 of tile4)
```

### Per-Tile BsmBI Reaction Contents

For a tile in SB_i, the BsmBI (3'WT) reaction assembles:
1. **Oligo** (mutant tile + barcode)
2. **Partial fragment**: gene content from tile end to SB_i end (may be 0 if tile is last in SB)
3. **Full SB blocks**: complete SBs from SB_{i+1} through SB_n
4. **Cassette fragment**: PolIII (+ intergene elements if present)

Overhangs in the BsmBI reaction for this tile:
- oh2 (tile → partial fragment junction)
- SB boundary OHs between this SB and subsequent SBs
- oh3 (last gene content → cassette junction)
- oh_cassette (if cassette is a separate fragment)

### Per-Tile Overhang Exclusion (Key Improvement)

**Only check overhangs within the same tile's reaction for collisions.**

Old (global): ALL oh2 values excluded from ALL superblock junction OH candidates
→ Fails because 4-nt sequences appear many times across a long gene

New (per-tile): For tile T's reaction, only check:
- oh2_T (this tile's oh2)
- oh3 (fixed, same for all tiles)
- SB boundary OHs visible to tile T (those between T's SB and the end)

### Collision Resolution

If a SB boundary overhang collides with oh3 or with another visible overhang:
1. Try shifting the SB boundary by ±1 tile
2. If no shift resolves it, try the next-best tile boundary

### Sizing Constraints

Each SB's gene content must fit within `max_sub_length = max_block_length - 22`:
- Non-last SBs: just gene content from SB start_nt to SB end_nt
- Last SB: gene content + PolIII length (+ cassette length if attached)

### Block Counting

Per SB with N tiles:
- **Tile blocks**: 2×(N-1) — each interior tile boundary needs a BsaI (5'WT) and BsmBI (3'WT) partial fragment
- **Full SB blocks**: 2×(n_SB-1) — each non-terminal SB needs both a BsaI and BsmBI version

### New Functions

```
partition_tile_superblocks(tiles, gene_len, polIII_len, max_sub_length, oh3=NULL)
  → Returns: list(n_superblocks, superblocks_df, n_collisions, block_count)

get_tile_reaction_overhangs(partition_result, tile_idx, tiles, oh3, enzyme_context)
  → Returns: character vector of all overhangs in that tile's reaction
```

#### Implementation Plan

**Step 1: Add P_eff data (efficiency metric)**

P_eff requires the raw diagonal count `M[X][RC(X)]` for each overhang, which we don't
currently store directly. Two approaches:

- **Option i (preferred):** Extract from the pairwise matrix. We already have
  `load_pairwise_matrix("potapov_18h")` which returns a 256×256 matrix where
  `mat[X, X]` = correct ligation count. Compute:
  ```r
  diagonal <- diag(mat)  # M[X][RC(X)] for all 256
  max_diag <- max(diagonal)
  P_eff <- diagonal / max_diag
  ```
- **Option ii:** Hard-code P_eff values alongside the existing fidelity data in
  `builtin_overhang_fidelity()` (add an `efficiency` column).

Preferred: Option i, since the pairwise matrix is already loaded in `plan_assembly()`.

**Step 2: Create `oogga_score()` helper**

```r
#' Compute OOGGA-style overhang score with HF set bonus
#'
#' Score = P_fid(oh) * P_eff(oh) * (1 + w_hf * (oh in HF set))
#'
#' @param oh Character, 4-nt overhang sequence
#' @param fid_lookup Named numeric vector (overhang -> fidelity)
#' @param eff_lookup Named numeric vector (overhang -> efficiency)
#' @param hf_set Character vector of HF overhangs
#' @param w_hf Numeric, HF bonus weight (default 0.5)
#' @return Numeric score
oogga_score <- function(oh, fid_lookup, eff_lookup, hf_set, w_hf = 0.5) {
  fid <- if (oh %in% names(fid_lookup)) unname(fid_lookup[oh]) else 0.5
  eff <- if (oh %in% names(eff_lookup)) unname(eff_lookup[oh]) else 0.5
  in_hf <- oh %in% hf_set
  fid * eff * (1 + w_hf * in_hf)
}
```

**Step 3: Update the 3 scoring locations**

All three currently use `score = 10 * in_HF + fidelity` (or a variant). Replace with
`oogga_score()` calls. The key change is that the score is now **multiplicative** (fid × eff)
rather than **additive** (10 * in_HF + fidelity).

| Location | Current scoring | New scoring |
|----------|----------------|-------------|
| `precompute_boundary_scores()` line 611 | `10*(oh1_in+oh2_in) + 2*oh1_pw + oh2_fid + penalty` | `oogga_score(oh1) + oogga_score(oh2) + pairwise_bonus(oh1,oh_L)` |
| `optimize_split_points()` line 1038 | `10*in_hf + fid` | `oogga_score(oh)` |
| `dp_solve_superblock_splits()` line 1193 | `10*in_hf + fid` | `oogga_score(oh)` |

Note: `precompute_boundary_scores()` also uses `compute_set_fidelity()` for oh1 pairwise
fidelity with oh_L in the BsaI reaction (line 597). This context-dependent pairwise
scoring should be KEPT — it's more accurate than OOGGA's context-independent approach.
The oogga_score provides the base, and the pairwise bonus adds context-awareness.

**Step 4: Add constants**

In `R/constants.R` or at the top of `R/06_overhang_selection.R`:
```r
DEFAULT_HF_BONUS_WEIGHT <- 0.5  # w_hf in oogga_score
DEFAULT_FIDELITY_WEIGHT <- 1.0  # w_fid (for future tuning)
DEFAULT_EFFICIENCY_WEIGHT <- 1.0  # w_eff (for future tuning)
```

- Test that `oogga_score()` returns higher values for HF overhangs than non-HF ones

floor-penalty provides a hard safety threshold.
